# 見た目の決まり

kinari-md が決めるのは、本文（変換した Markdown）の見た目だけ。画面の帯・ボタン・一覧などはアプリが決める。
見た目は md-leaf の本文を引き継ぐ（立ち上げで、見本のページ `docs/agreed-screens/sample-*.png` で合意）。

## トークン

- トークンファイル：<!-- 立ち上げの土台づくり（/dev-build）で決める。立ち上げのあいだは docs/tokens.css に仮置き -->
- トークンは2つに分かれる
  - **アプリが持つもの**：地・面・文字・枠・差し色・意味の色・書体・文字の大きさの段階・角丸・余白。名前はシリーズで共通にし、kinari-md は名前で読むだけで値を持たない
  - **kinari-md が持つもの（Markdown の色）**：code-bg・code-line・code-keyword・code-string・code-comment・callout-abstract・callout-important・callout-caution。ライトとダークの2組で持つ
  - 理由：Markdown の表示だけが使う色をアプリごとに書くと、2つのアプリでずれるため。地や差し色はアプリの画面全体と揃っている必要があるので、アプリから読む
- 見本のページでは、アプリが持つものも代わりに決める（値は md-leaf の今の値。差し色の江戸紫は memory-forge の値）
- コードでもプロトタイプでも、トークンにない値（`p-[13px]`、`#3366ff` など）を使わない
- 色はライトとダークで2組あり、同じトークン名で切り替わる。本文の CSS でライト・ダークを分けて書かない。どちらかは、アプリが `<html>` に付けた `data-theme` で決まる

## 雰囲気

「紙と若葉」を引き継ぐ。ライトは生成りの地に墨の文字、ダークは墨の地に生成りの文字で、本を読むように長い文章を落ち着いて読める見た目にする。
- 理由：シリーズのアプリはどれも、Claude が作った文章を読むことが中心なので、情報の多さより、文字の大きさと行間の広さを優先する
- ダークで読むことが多いので、ライトとダークの両方で、見分け（コールアウトの色、コードの色分け）が同じように保てることを確かめる

## 色の使い分け

| トークン | 使う場面 |
| --- | --- |
| bg | 本文の地（アプリの地と同じ） |
| surface | 図の地 |
| text | 本文、図の線と文字 |
| muted | 画像の下の代わりの文字 |
| border | 見出しの下線、表の線、図・画像の枠 |
| accent | リンク、図の強調 |
| info・success・warning・danger | コールアウトの note・tip・warning・danger の色 |
| callout-abstract・callout-important・callout-caution | コールアウトの abstract・important・caution の色 |
| code-bg | コードブロックと文の中のコードの地 |
| code-line | コードブロックの行番号 |
| code-keyword・code-string・code-comment | コードの色分け |

## 余白と並べ方

- 余白はトークンの段階だけを使う
- 本文の幅（prose の幅など）はアプリが決める。kinari-md は与えられた幅いっぱいに出す
- スマホでは、コールアウト・コードの内側の余白を狭くする（PC では広く戻す）
  - 理由：スマホの狭い幅では、余白が広いと折り返しが増えて読みにくい
- 本文の中の横に長いもの（コード・表・数式・図）は、それぞれの枠の中でスクロールし、本文全体は横にスクロールさせない

## 文字

- 本文と見出しは明朝（font-body）。コールアウトの見出し・表・図・画像の代わりの文字はゴシック（font-ui）。コードは等幅（font-mono）
  - 理由：読むものと操作するものを書体で分けると、本文に目が向きやすい。表は細かい文字が多く、明朝だと読みにくい
- 見出し：h2（下に区切り線）、h3、h4 以下は本文の大きさの太字。ノートの題（h1）はアプリが出す
- 本文の文字の大きさは、アプリが `--reading-size` で決める。見出しなどの大きさは、本文の大きさに倍率をかけて決める
  - 理由：md-leaf の文字の大きさのメニューのように、アプリが本文だけの大きさを変えられるようにするため
- 行間は relaxed。字間は詰めない（かな・約物は正方形の枠のまま）
  - 理由：句読点のあとが窮屈に見えるより、等幅に並ぶほうが読みやすい

## 部品の使い分け

- コールアウト：左に太線、薄い地、見出しにアイコンと題（題がなければ種類ごとの日本語の題）。折りたたみ（`> [!note]-`）は見出しの右に矢印を出し、最初は閉じておく
  - 見出しはゴシックの小さめの太字で、種類の色。中身は本文と同じ明朝
  - 色は note→info、tip→success、warning→warning、danger→danger、abstract・important・caution はそれぞれの Markdown の色の7色。別名と決まりにない種類の扱いは md-leaf と同じ
  - 理由：意味を分けて使う組（abstract と info、tip と important、warning と caution）は、色も違えば一目で分かる。種類ごとに全部の色を分けると似た色が増え、ライト・ダークの両方で見分けを保つのが難しい
  - 薄い地は、種類の色を bg に混ぜて作る（トークンを増やさない）
- コードブロック：code-bg の地に等幅の文字。色分けは code-keyword・code-string・code-comment の3色だけで、ほかは text の色。長い行は折り返さず、枠の中で横にスクロールする
  - 行番号：呼ぶ側が付けると選んだブロックだけに付ける。code-line の色で右にそろえ、選んで写すときに含めない
- 文の中のコード：code-bg の薄い地の等幅の文字。色分けしない
- 表：ゴシックの小さめの文字。見出しの行と各行の間に border の線を引き、縦の線と地は付けない。表の中のコードは地を付けず等幅にするだけ。列の幅は文字数の段階で決め、日本語は禁則で折り返す
  - 理由：行の線で区切ってあるので、地を付けると細かく見える
- 図（Mermaid）：surface の地に border の枠。図の線と文字は text の色、強調は accent、字はゴシックの小さめの字。ライト・ダークが変わったら描き直す。図は縮めず、収まらなければ枠の中で横にスクロールする
  - 理由：縮めると字が読めなくなる
- 数式：長ければ数式の中で横にスクロールする
- 画像：本文の幅に収め、小さい画像は引き延ばさない。角を丸め、border の枠。画像だけの段落では、下に代わりの文字を muted の小さな文字で中央に出す
- 引用：飾りを付けず、ふつうの段落と同じに出す（md-leaf と同じ）

## 見本のページ

- 変換した Markdown を、書き方ごとに並べる。上に、ライト/ダーク・差し色・本文の文字の大きさを切り替えるボタンを置く
- アプリでの使い方の例（memory-forge の問題文と選択肢など）も並べる。ただし選択肢の行の見た目は見本のための仮のもので、kinari-md の見た目ではない（本物はアプリが持つ）

## 状態の見せ方

- 書き方を間違えた Mermaid の図など、描けないものは、元の文字をコードブロックとして出す（md-leaf と同じ）
- 読み込み中・エラー・0件の見せ方はアプリが決める

## 文言

- コールアウトの種類ごとの題は日本語（「メモ」「ヒント」「注意」など。md-leaf と同じ）
