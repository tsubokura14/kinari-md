# 概要

## 目的

Claude が作った Markdown をブラウザで読むアプリのシリーズ（md-leaf、memory-forge、これから作るもの）で、Markdown を画面に出す部分（変換の処理と、変換したものの見た目）を1か所にまとめる。片方のアプリで直すともう片方とずれる、今の「書き写して揃える」状態をなくす。

## 使う人

- シリーズのアプリ（md-leaf、memory-forge）。アプリは、このパッケージを GitHub のタグを指定して npm で入れる
- それを作る本人と AI。Markdown の表示を直すときは、アプリではなくこのリポジトリで直す
- アプリを使う本人は、ダークモードで使うことが多い。ダークをライトと同じだけ大事に扱う
- 見本のページは本人だけが見る。PC とスマホで、変換した Markdown の見え方を確かめるのに使う

## 主な機能

- Markdown の変換（`kinari-md/markdown`）：Markdown を HTML にする。書き方と見た目は md-leaf に揃える
  - GFM、フロントマター（`title` を取り出す）、コールアウト（Obsidian 標準の種類と折りたたみ）、コードの色分け、数式、表、改行と日本語の強調（Obsidian と同じ読み方）
  - 見出しの一覧（目次の元）を返す。目次をどこにどう出すかはアプリが決める
  - 呼ぶ側が使う書き方を絞れる（例：memory-forge の選択肢ではコードだけ）。どこで何を使うかは各アプリが決める
  - リンクと画像の書き換えは、アプリから関数で渡す（ノートの置き場所はアプリごとに違うため）
  - サニタイズする（memory-forge の問題文はデータベースから来るため）
- 変換したものの見た目（本文の CSS）：見出し・段落・リスト・リンク・コード・表・コールアウト・数式の見た目。md-leaf の本文の見た目を移す
  - 地・文字・枠・差し色・意味の色・書体は、アプリのトークン（シリーズで共通の名前）を読む。名前は `bg`・`surface`・`text`・`muted`・`border`・`accent`・`success`・`warning`・`danger`・`info`・`font-body`・`font-ui`・`font-mono` など
  - Markdown の表示だけが使う色（コードの色分けの keyword・string・comment、コードの地と行番号、コールアウトの abstract・important・caution）は、このパッケージがライトとダークの2組で持つ
  - コールアウトの色は意味の色に当てる（note→info、tip→success、warning→warning、danger→danger）
  - ライトかダークかは、アプリが `<html>` に付けたもの（`data-theme`）に従う。system・light・dark の選び方はアプリが持つ
  - 本文の文字の大きさは、アプリが外から変えられる（md-leaf の文字の大きさのメニュー）
- コードブロック：言語に合わせて色を付ける。行番号を付けるかを選べる（memory-forge の問題文で使う）
- Mermaid の図：ブラウザで描く。ライトとダークに合わせた色で描く
- 見本のページ：変換した Markdown（書き方をひととおり）を並べたページ。ライトとダークを切り替えて見られる。画像を撮って比べるのにも使う。本人だけが見られる形でデプロイし、スマホでも確かめられる

### アプリが移る順番（机上の検討で合意したもの）

1. 各アプリの中で名前を揃える（このリポジトリの外。tsubokura14/memory-forge#131、tsubokura14/md-leaf#32、tsubokura14/md-leaf#33）
2. このリポジトリを立ち上げる。最初に、このリポジトリとアプリを手元で同時に直す方法を試して決める（`npm pack`、`file:`、タグを打つ）。Turbopack はプロジェクトの外に link したファイルを扱いにくいため
3. md-leaf の変換と本文の見た目を移して v0.1.0。md-leaf が替える（画面は変えない）
4. memory-forge が替え、Prism を外す（見た目が変わるので、memory-forge の /dev-proto から）
5. テンプレートと各アプリの決まりに「Markdown の表示は kinari-md で直す」と書く。版を上げる PR の出し方を決める

## やらないこと

- Markdown の表示のほかの共通化。トークン（色・書体・角丸・影の値）、画面の部品（ボタン・帯・アイコン・テーマの切り替え）は、各アプリが持ち、名前だけを揃える。共有したくなったら、そのとき別のパッケージを考える
- 同じバックエンド（サーバー）を共有すること。共有するのはコードだけで、各アプリの中で動く
- ノートや問題の読み込み、ファイルの置き場所（アプリごとに作りが違う）
- 目次の画面の部品、本文の文字の大きさのメニュー（md-leaf だけのもの）
- 見本のページを誰でも見られる形で公開すること
- npm への公開（GitHub のタグで配る）
- 1つのリポジトリの中に複数のパッケージを置くこと（GitHub のタグで入れると、一番上のパッケージしか入れられないため）
- 使うアプリがまだない書き方を先に作ること

## 技術

| 用途 | 使うもの | 選んだ理由 |
| --- | --- | --- |
| 言語 | TypeScript（ビルドせずに配り、アプリの Next.js の `transpilePackages` でビルドする） | このリポジトリにビルドの手順が要らない。2つのアプリとも Next.js 16 |
| Markdown の変換 | unified（remark・rehype）、highlight.js、KaTeX、mermaid（ブラウザで描く） | md-leaf の今の作りをそのまま移す |
| 配り方 | GitHub のタグ（`github:tsubokura14/kinari-md#v0.1.0`） | npm への公開も鍵も要らない。2つのアプリもこのリポジトリも公開 |
| 見本のページ | 同じリポジトリの中の、見本用の Next.js 16 のアプリ（パッケージには入れない） | 2つのアプリと同じ入れ方（transpilePackages・Tailwind・Server Components）を、ここで先に試せる |
| デプロイ先 | Vercel（Hobby）。見本のページだけ | 無料で、2つのアプリと同じ。パッケージ自体はデプロイしない |
| 見られる人の絞り方 | Vercel の認証（Vercel Authentication）を全部のデプロイにかける | 本人の Vercel のログインだけで見られ、ログインの仕組みと鍵を作らずに済む |
| データベース・認証・個人情報 | なし | 保存するデータがない |
| テスト | Vitest、見本のページの画像を、Playwright の公式の Docker イメージに日本語の書体を入れたイメージで比べる（ライトとダーク、スマホと PC の幅） | md-leaf の変換のテストをそのまま移せる。ダークで読むことが多いので、ダークも比べる |
| Lint・整形 | ESLint（`eslint-config-next`）、Prettier | 2つのアプリと同じ道具と設定で書ける |
| 版の付け方 | v0.x のあいだは、版を上げるたびに変わったところを `CHANGELOG.md` に書く。名前を変えるなどの壊れる変更も、版を上げて入れてよい | 使うアプリは2つとも自分のもので、アプリで版を上げるときに変わったところが分かれば足りる |

## 用語

| 用語 | 意味 |
| --- | --- |
| シリーズ | Claude が作った Markdown を読むアプリの集まり。今は md-leaf と memory-forge |
| アプリ | このパッケージを入れて使う、シリーズのアプリ |
| 本文 | 変換した Markdown を画面に出したもの |
| トークン | 色・書体・角丸などの見た目の値。各アプリが持ち、名前はシリーズで揃える |
| 差し色 | アプリごとに違う1色（md-leaf は若葉の緑、memory-forge は江戸紫）。トークンの `accent` |
| 意味の色 | 成功・注意・危ない・情報を表す色（`success`・`warning`・`danger`・`info`） |
| Markdown の色 | Markdown の表示だけが使う色（コードの色分けなど）。このパッケージが持つ |
| 見本のページ | 変換した Markdown を並べ、見え方を確かめ、画像を撮って比べるためのページ |
